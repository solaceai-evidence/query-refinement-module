# Audit: Query Refinement Module (October 2026)

**Scope.** This audit covers the code, the security review and the move of the user interface to Chainlit. It was done ahead of the Cochrane presentation of *"Implementing a Schema-Guided Conversational System for Transparent Query Formulation in AI-Assisted Evidence Synthesis"*.

**Branch.** `audit/chainlit-parity`, commits `b00ce07` to `6065e97`.

**Model.** `anthropic/claude-sonnet-4-6`.

**Status at the end of this audit:**
- 535 automated tests pass. Another 65 skip themselves because they need a live server or LLM.
- Continuous integration runs the test suite on every push.

## 1. Abstract claims and evidence

Status key: ✅ supported by evidence in the repository · 🟡 partly supported · ⏳ planned (the abstract itself says this is still in progress).

| Claim in the abstract | Status | Evidence |
|---|---|---|
| Multi-turn refinement of free-text questions | ✅ | Chainlit UI and API share one persisted workflow (`application/chainlit_adapter.py` → `RefinementApiService`). End-to-end browser runs were done on the real LLM. |
| Explicit control commands for navigation and completion | ✅ | `/back /skip /done /clear /restart /submit /status /steps /help` are available as buttons and as typed commands. Destructive commands ask for confirmation. Every command is audit-logged. |

| Access control | ✅ | Login for the chat UI. Frameworks are visible per user. One-workflow limit. Monitoring endpoints need superuser rights. Admin access to the audit log. Allow-list for model overrides. |

| Runtime monitoring | 🟡 | The circuit breaker now trips on real outages, which it never did before. Trace and audit events exist. Per-call token, latency and cost metadata (`refinement_step_metadata`) is still not written. |
| Evaluation: completeness, specificity, search-readiness | 🟡 | Search-readiness has a benchmark (§3). Completeness and specificity have scenario checks (§3.2) but no aggregate metric yet. |

## 2. Findings and resolutions

Severity: **C**ritical · **H**igh · **M**edium · **L**ow.

### Security and data protection

| Sev | Finding | Status |
|---|---|---|
| C | An Anthropic API key is in git history (commit `3fddea1`). | **Rotate the key yourself.** History was deliberately not rewritten. |
| C | A database backup with 117 real users was tracked in git, and local DB files were not excluded from Docker images. | Removed from tracking. `.gitignore` and `.dockerignore` now exclude them. |
| H | The chat UI had no authentication and wrote nothing to the database or audit log. | Fixed (Phase 1). |
| H | `/monitoring/llm-health?test_connection=true` had no authentication, so anyone could make it spend paid LLM calls. | Now requires a superuser. |
| M | Clients could override the model used by `/represent`, `/construct` and `/expand` with any model. | Overrides are limited to the configured model and `LLM_ALLOWED_MODEL_OVERRIDES`. |
| M | The SSRF check on `forward-to-qa` only blocked literal private IP addresses. | It now resolves the hostname via DNS when sending. |
| L | Admin routes were served under a doubled path, `/api/v1/api/admin/...`. | Changed to `/api/v1/admin/...`. |

### Reliability

| Sev | Finding | Status |
|---|---|---|
| H | During an LLM outage, the dimension being answered was silently marked complete in the CLI and in-memory paths. | Fixed. A typed `LLMUnavailableError` is raised, the API returns 503, and the answer is not saved. |
| H | The circuit breaker never tripped, because LiteLLM's errors are not subclasses of `TimeoutError`/`ConnectionError`. | Fixed. Timeouts and 5xx errors are now retried and counted. An open circuit fails immediately instead of retrying. |
| H | `forward-to-qa` raised `AttributeError` on every call with default settings. | Fixed. |
| M | The CLI made up to 5 LLM calls per user answer with no new input. | Now one call per answer. |
| M | The Chainlit app would have failed to log in under Docker: Chainlit sets up its own data layer whenever `DATABASE_URL` is set. | That data layer is now disabled. |
| M | In Chainlit 2.11, opening a dialog from inside a button callback leaves the UI frozen in a "running" state. | Confirmations and the survey are now driven by follow-up actions instead. |

### Correctness and traceability

| Sev | Finding | Status |
|---|---|---|
| H | Each follow-up history row recorded the *next* question against the user's answer. | Fixed. |
| H | Suggested answers were lost whenever the session was saved and reloaded. | Fixed. |
| M | `/back`, `/restart` and `/clear` deleted the user's answers from the database with no record. | They are now archived in the audit log before deletion. |
| M | `/clear` never reached the database. | Fixed. |
| M | `dimensions_specifications` came from the LLM and was keyed by display name, which contradicts `docs/API.md`. | Now built deterministically and keyed by id. |

### Search methodology

| Sev | Finding | Status |
|---|---|---|
| H | Agent C was told to build **4 AND-blocks by default**. This produced invented blocks (e.g. a "setting" block of comorbidities), generic "effectiveness" blocks, and outcome blocks. Each AND-block reduces sensitivity. | The prompt now follows a sensitivity-first, minimal-concept approach, and deterministic validation runs afterwards. See §3. |
| M | "No restriction" answers were written into the statement and then turned into search concepts. | Fixed in Agent A and Agent B. |
| M | In 10% of baseline runs, the concept blocks did not match the Boolean query, so a downstream connector would have run a different search from the one shown. | Agent C must now mirror the blocks exactly, and alignment is checked: 100% aligned after the fix. |

## 3. Evaluation results

### 3.1 Search-readiness benchmark

`scripts/evaluate_search_quality.py` runs 10 fixed scenarios, twice each, across 5 frameworks and several domains: health, education, law, humanitarian and public health. Each scenario fixes the dimension values a dialogue would produce, including skipped and "no restriction" answers. That way, differences between runs come from the pipeline rather than the dialogue. All indicators are deterministic. Raw outputs are in `eval_results/`, and `scripts/compare_search_quality.py` rescores every run with the same code.

| Metric (20 runs each) | Baseline | Final (v3) |
|---|---|---|
| Mean AND-blocks | 4.4 | 3.1 |
| Search-ready (no detected defect) | 65% | 90% |
| Concept blocks aligned with the Boolean query | 90% | 100% |
| Runs with an ungrounded (invented) block | 25% | 10%¹ |
| "No restriction" text in the clarified statement | 30% | 0% |
| Coverage of the user's original question | 0.99 | 0.95² |
| Runs with errors | 0 | 0 |

¹ The remaining flags are a known false positive: "how common" → *prevalence* is a legitimate concept that the lexical grounding check cannot see.
² Lower coverage reflects deliberate omissions, e.g. "prevalence" in a COCOPOP prevalence question. An intermediate version (v2) reached 95% search-readiness but dropped core concepts, such as "mental health" in an association question, so it was rejected.

**Methodological notes and limitations:**
- The checks are deterministic and work in any domain. Automatic repair only *drops* AND-blocks, so it can never lose a record the original query would have found.
- The indicators measure structural search-readiness, not retrieval performance. Measuring recall and precision needs reference sets of included studies, e.g. from published Cochrane reviews. That fits naturally into the planned baseline comparison.
- Only one model was tested, with n = 2 runs per scenario.

### 3.2 Scenario checks for dialogue and synthesis

`scripts/evaluate_pico_advanced.py` and `scripts/evaluate_cocopop.py` were repaired: they had been calling a removed function.

| Framework | Scenarios passing | Synthesis checks passing | Remaining differences |
|---|---|---|---|
| pico_advanced | 2/2 | 2/2 | One check is marked as a known divergence: the framework deliberately asks about secondary study types. |
| cocopop | 0/4 | 3/4 | The model puts the exposure (flood, drought) in *context* rather than *condition*, and gives more specific geography than expected ("India and Pakistan" instead of "South Asia"). **These expectations need a methodological decision; they were not edited.** |

## 4. Operational reliability check

A provider outage was simulated mid-dialogue by redirecting the LLM to a closed port.

**First failed answer:**
- It returned **HTTP 503** with the message "please send it again", after three attempts with backoff (about 7 s).
- The dimension stayed active and no follow-up row was saved.

**Circuit breaker:** it opened after 3 failures. After that, requests failed in under 0.1 s instead of waiting through retries.

**Synthesis:** a failure during synthesis now also returns 503, and the answers already saved are kept.

## 5. Deferred items

**Before the conference:**
- Rotate the leaked API key.
- Decide on the COCOPOP evaluation expectations (§3.2).
- Pilot the restored survey with 3–5 users to check usability and perceived control.

**Framework design:**
- Add a per-dimension flag in `frameworks.yaml` (e.g. `search_concept: false`). This would stop dimensions such as MPH "research domain" or "data source" from becoming search blocks.

**Monitoring:**
- Write per-call tokens, latency and cost to `refinement_step_metadata`.
- Use a persistent tracing provider for the API and Chainlit, instead of the current no-op.

**Domain coverage:**
- Agent B's query roles and Agent D's geography broadening are biased towards health and humanitarian topics, as is the rule that maps "recent" to a year range.
- This is acceptable for a Cochrane audience, but should be stated as a limitation of a platform that aims to work in any domain.

**Code health:**
- `core.py` is 2,300 lines and should be split.
- There are two near-identical sync/async completion paths, and five separate copies of the JSON-extraction logic.
- Dead code includes `_run_monolithic_synthesis` and unused CRUD helpers.
- Importing `application` before `api` causes a circular import.
- There is no linter configured.
- The `_last_llm_metadata` race is harmless: it only affects trace metrics.

**Housekeeping:** stray `.env` templates and leftover prompt dumps in `docs/`.
